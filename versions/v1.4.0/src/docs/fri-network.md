# 🌐 跨网络联机：SakuraFrp 穿透 / 蒲公英·米西·ZeroTier 组网

> 适用场景：**固定朋友开黑、不在同一局域网、不想买服务器、零预算**。
> 核心前提：GinyScreen 的**信令服务器**必须能被所有成员访问；而**语音/屏幕是 WebRTC P2P 直连**，走哪条「找到服务器」的路与语音质量没有直接关系。

## 0. 原理：信令 ≠ 媒体

```
开服者 PC ──┐                 ┌── 好友 PC
            │  ① 信令(找房间)   │   WebSocket(Socket.IO)
            └──► 服务器 ◄──────┘
                  │
  ② 语音/屏幕：双方浏览器 WebRTC P2P 直连（STUN 打洞），不经过服务器
```

- **信令**：极低频、小包（进房、换频道、交换 SDP/ICE），每月流量占用可忽略
- **媒体**：语音（Opus）+ 屏幕视频，P2P 直连，服务器零转发
- 结论：**内网穿透/组网只负责「让好友找到开服者的服务器」**；语音是否通畅取决于双方 NAT 能否打洞

## 1. 方案一：组网（推荐，语音最稳）

**通用流程**：所有人安装同一个组网工具并加入同一网络 → 开服者在 GinyScreen 首页选「开房间」填端口（默认 3000），把「本机可访问地址」里的**虚拟 IP:端口** 发给好友 → 好友首页选「加入房间」填入 → 自动重启并进入。

> 当前选定 **ZeroTier** 为主方案（免费、P2P 直连、无 HTTP 拦截），完整教程见 1.3；蒲公英 / 米西作为备选。

### 1.1 蒲公英（贝锐）—— 门槛最低，国内稳定

| 免费额度 | 说明 |
|---------|------|
| 1 个网络 / 最多 3 个成员（含硬件和软件） | 超过需购买授权 |
| P2P 点对点不限速 | 经转发服务器时每节点 2 Mbps |

1. 官网 [pgy.oray.com](https://pgy.oray.com) 用手机号注册
2. 下载「蒲公英客户端」（Windows）并登录
3. 创建网络 → 邀请好友加入（好友也装客户端登录同一网络）
4. 确认各自拿到 `10.x.x.x` / `172.x.x.x` 开头的虚拟 IP
5. 开服者把**自己的虚拟 IP:端口** 发给好友，好友在 GinyScreen 首页「加入房间」填入

> 语音（Opus ≈ 24~64 kbps）在虚拟局域网内 P2P 直连，免费限速不影响。

### 1.2 米西开黑 —— 免费低延迟 P2P 组网

1. 下载「米西开黑」并登录
2. 创建联机房间（选对应游戏或通用）→ 好友加入同一房间
3. 成员头像右上角延迟变绿即组网成功
4. 开服者在 GinyScreen「本机可访问地址」里找到米西分配的虚拟 IP 发给好友

> 米西本身也带语音/视频/屏幕，可以**只用它组网**、继续用 GinyScreen 语音。

### 1.3 ZeroTier —— 当前选定主方案（免费 P2P 组网，官方免费 1 网络 / 25 设备）

> 数据面走 UDP 9993 打洞 **P2P 直连，不经过 HTTP**，不存在 SakuraFrp 那种 501 拦截问题；免费额度对 2~4 人固定开黑完全够用。唯一注意：管理后台 [my.zerotier.com](https://my.zerotier.com) 在境内偶尔慢，多刷新或用手机热点即可。

**第 0 步 · 安装（开服者 + 每个好友都要装）**
1. 官网下载 Windows 客户端：<https://www.zerotier.com/download/>（安装后右下角托盘出现 ZeroTier 图标，服务自动运行）
2. 下载慢可用 GitHub Release 加速镜像

**第 1 步 · 开服者创建网络（只需操作一次）**
1. 打开 <https://my.zerotier.com> 注册 / 登录（邮箱即可）
2. 点 **Create A Network** → 进入网络详情页
3. 记下 **Network ID**（16 位十六进制，形如 `a1b2c3d4e5f6a7b8`）；网络类型保持 **Private**

**第 2 步 · 所有人加入网络**
1. 每台电脑：托盘 ZeroTier 图标 → **Join New Network...** → 粘贴 Network ID
2. 或命令行（管理员）：`"C:\Program Files (x86)\ZeroTier\One\zerotier-cli.bat" join a1b2c3d4e5f6a7b8`

**第 3 步 · 授权成员并拿虚拟 IP（开服者在 Central 网页操作）**
1. my.zerotier.com → 进入你的网络 → **Members** 列表
2. 把开服者自己和每位好友的节点都勾上 **Auth**（否则拿不到 IP）
3. 授权后每行出现 **Managed IP**（形如 `10.147.20.3` / `192.168.196.3` / `172.24.x.x`）

**第 4 步 · 验证组网已通**
- 双方先 ping 对方的虚拟 IP：`ping 10.147.20.3`
- 或看本机状态：`"C:\Program Files (x86)\ZeroTier\One\zerotier-cli.bat" listnetworks`（status = OK 且有 assignedAddresses）
- ping 不通：确认两端都已 Auth、服务在运行；查 Windows 防火墙（ZeroTier 安装时会自动加 UDP 9993 入站规则）和杀毒软件

**第 5 步 · 用 GinyScreen 联机**
1. 开服者：首页「开房间」→ 端口默认 `3000` → 保存自动重启开服
2. 开服者在「本机可访问地址」里找 **ZeroTier 虚拟 IP 那一行**（形如 `10.147.20.3:3000`）发给好友
3. Windows 防火墙需放行**入站 TCP 3000**（开服端口）
4. 好友：首页「加入房间」→ 填 `10.147.20.3:3000` → 保存自动重启进入（虚拟 IP 自动走 HTTP）

**国内与疑难排查**
- 控制台打不开：多刷新 / 换网络；好友可先用客户端 Join，授权由开服者稍后在 Central 完成
- 长期打洞失败（校园网 / 对称 NAT）：有公网 VPS 可自建 **Moon** 服务器；否则换蒲公英 / 米西
- 虚拟 IP 一般固定；重装系统 / 换机器会变，以 Central 上 Managed IP 为准

## 2. 方案二：SakuraFrp 内网穿透（好友零安装）

只推荐给「开服者没有公网 IP、想让好友填一个公网地址直接访问」的场景。

### 免费额度（需实名）

| 项目 | 额度 |
|------|------|
| 隧道数量 | 2 条 |
| 单隧道带宽 | 10 Mbps |
| 每月流量 | 5 GiB（每日签到可增加） |
| 实名认证 | 必须（国内法规要求） |

### 创建 TCP 隧道步骤

1. 注册 [SakuraFrp](https://www.natfrp.com/) 并完成实名认证
2. 管理面板 → 创建隧道：
   - 类型：**TCP**
   - 本地地址：`127.0.0.1`
   - 本地端口：GinyScreen 首页自选端口（默认 `3000`）
3. 下载并登录 SakuraFrp 启动器（Windows 客户端）→ 启动该隧道
4. 得到公网地址，形如 `123.45.67.89:23456`（随机远程端口）
5. 把公网域名地址发给好友：好友在 GinyScreen 首页「加入房间」填入 `frp-oil.com:18565` → 自动重启并进入（域名自动走 HTTPS）

> 地址协议自动补全：**域名**（如 SakuraFrp 隧道 `frp-oil.com:18565`）→ `https://`；**IP / localhost / 组网虚拟 IP** → `http://`；不带端口时默认补 `3000`。

### ⚠️ 必读：国内节点会拦截明文 HTTP，必须开启「自动 HTTPS」

SakuraFrp 国内节点会对隧道上的明文 HTTP 流量直接返回 501 拦截页（合规要求）。GinyScreen v1.3.1 起，域名地址会自动走 HTTPS，但**开服者必须先在隧道上启用 HTTPS 终结**，否则 HTTPS 请求会被透传到本机明文 HTTP 服务器而握手失败：

1. 打开 SakuraFrp 管理面板 → 隧道列表 → 编辑你的 TCP 隧道（如 `mc11111`）
2. 找到「自动 HTTPS」→ 选择 **启用/自动**
3. 保存并**重启该隧道**（或在启动器里重启 frpc）
4. 之后用 `https://隧道域名:远程端口`（即 `frp-oil.com:18565`）访问即可，本地 GinyScreen 服务器保持默认明文 HTTP 即可

> 原理：自动 HTTPS 由 frpc 对外终结 TLS（带可信证书），再以明文 HTTP 转发给本机服务，因此**本地无需任何证书配置**，好友的桌面版/浏览器版都能直接使用。

### 桌面版与浏览器版的差异

- **桌面版 exe**：远程明文 HTTP 已被标记为 Chromium 安全来源，**麦克风可直接用**
- **浏览器版**：明文 HTTP 下 `getUserMedia` 会被浏览器拦截，需 HTTPS → 用 SakuraFrp 的 HTTP/HTTPS 隧道并绑定自己的域名

### 防火墙与流量

- ✅ 隧道是**出站**连接，Windows 防火墙**无需放行入站**
- ⚠️ 每月 5 GiB 只消耗在信令/页面资源上（低频小包），日常开黑够用；**语音/屏幕不走隧道**

### 为什么语音不走隧道，还可能没声音

- 家庭宽带（Full Cone / 普通 NAT）→ STUN 打洞基本成功，语音 P2P 直连，延迟最低
- 校园网 / 公司网（对称 NAT）→ 打洞失败 → **能进房间但听不到声音**
- GinyScreen v0.6.0 起，打洞失败会在界面弹出诊断提示：「与 XX 的语音连接失败：公网打洞未成功，建议组网或检查防火墙」
- 遇到这种情况：改用**组网方案**（虚拟局域网内 NAT 变简单，语音基本必通），或按 README「进阶」配置 TURN 兜底

## 3. 三方案对比

| 维度 | ZeroTier（当前选定） | 蒲公英 | 米西开黑 | SakuraFrp 穿透 |
|------|----------------------|--------|---------|---------------|
| 客户端安装 | 所有人 | 所有人 | 所有人 | 只有开服者 |
| 免费额度 | 1 网络 / 25 设备 | 1 网络 / 3 成员 | 免费 P2P | 2 隧道 / 10 Mbps / 5 GiB/月 |
| 实名要求 | 邮箱 | 手机号 | 手机号 | 必须实名认证 |
| 语音稳定性 | 稳（P2P 打洞，依赖双方 NAT） | 最稳（虚拟网内 P2P） | 稳（P2P） | 取决于双方 NAT，严格 NAT 会失败 |
| 国内可用性 | 数据面稳定，控制台偶尔慢 | 稳定 | 稳定 | 稳定，但流量有限且明文 HTTP 被 501 拦截 |
| 适用场景 | 固定小团体（当前使用） | 2~3 人固定开黑 | 小圈子低延迟开黑 | 好友零安装、临时开黑 |

## 4. IPv6 直连（免装软件）

国内运营商宽带大多已分配公网 IPv6。双方都有 IPv6 时：

1. 开服者看首页「本机可访问地址」，找 IPv6 地址（形如 `[240e:xxxx:...]:3000`，端口为自选值）
2. 发给好友 → 好友在首页「加入房间」填入 → 自动重启并进入

> 服务器已默认**双栈监听**（IPv4 + IPv6），无需额外配置。

## 5. 排查手册

| 现象 | 排查 |
|------|------|
| 好友能进房间但听不到声音 | 打洞失败 → 改用组网方案；确认双方系统防火墙允许 GinyScreen（WebRTC 用随机 UDP 端口） |
| 填了虚拟 IP 还是进不去 | 先 `ping 虚拟IP` 确认组网已通；再核对 GinyScreen 地址端口没写错 |
| SakuraFrp 隧道流量涨得很快 | 正常只消耗信令；若涨得异常，确认没人把视频/屏幕走了隧道 |
| 换网络后连不上 | 组网 IP / 隧道地址会变，重新查看并更新服务器设置 |
| 浏览器版连远程地址麦克风不可用 | 浏览器限制明文 HTTP 麦克风 → 用桌面版 exe，或给隧道绑定域名开 HTTPS |
