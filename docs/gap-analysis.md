# GinyScreen 功能差距分析（现状 vs 预期语音软件）

> 基准：Discord / Mumble / TeamSpeak 3 / Kook / YY 的常用功能集。
> 验证方法：`node scripts/smoke-test.mjs`（信令 12 项）+ 浏览器自动化实测（菜单/弹窗/界面切换/频道加入）+ 双客户端信令验证。
> 结论：**核心闭环（房间 → 语音频道 → 通话 → 聊天 → 屏幕共享）已可用**；差距集中在权限管理、房间持久化、个性化与规模化。

## 二、与预期语音软件的差距（按优先级）

### P0 建议尽快补（影响“能用得像样”）
1. **房间/频道权限管理** — 目前任何人都能建房、进房、改频道；缺少：
   - 房主/管理员身份、房间密码/白名单
   - 踢人、禁言（mute）、锁频道
   - 频道创建/改名/删除（现在是固定 3 频道模板）
2. **断线重连** — 服务器重启或网络抖动后，客户端直接回到大厅且不自动重连。预期软件（Discord/Mumble）会自动重连并恢复频道。
3. **成员按人音量调节 / 单独静音某个人** — 开黑时常见（某人炸麦直接拉低）。

### P1 高价值（对齐主流体验）
4. **房间持久化** — 房间/频道状态是内存态，服务器重启即清空；应落盘（SQLite/JSON）或支持“固定房间号 + 服务器重启保留”。
5. **讲话音效与状态增强** — 入/离频道提示音、说话边框动效、文字聊天 Markdown/表情。
6. **本地服务端管理页** — 查看在线人数、房间列表、日志下载（自托管用户刚需）。
7. **屏幕共享增强** — 暂停共享、多屏选择记忆、带宽自适应（VP9/SVC 或降低帧率）。

### P2 远期（规模与生态）
8. **SFU 扩容**（>8 人/频道）：mediasoup 或 LiveKit（见 tech-alternatives.md）。
9. **账号体系 / 好友 / 私信**：超出“小圈子开黑”范围，需引入数据库与鉴权。
10. **移动端 / 降噪增强（RNNoise）/ 录音 / 变声**：路线图项。

## 三、技术债与风险
- **mesh 上行带宽**：8 人频道上行约 300~560 kbps/人，家用宽带足够；>8 人需 SFU。
- **严格 NAT**：需 TURN 兜底，README 已给环境变量注入方式，缺一键部署文档。
- **无端到端测试**：当前冒烟只覆盖信令层；音视频链路建议增加双浏览器自动化（授权虚拟麦克风/摄像头）。
- **Electron 打包体积**：~100MB 级，可后续启用 asar 压缩与按需加载。

## 四、验证结论
- 服务端信令 12/12 断言通过；浏览器自动化 28 项断言中 26 项通过（2 项为测试环境依赖：真实音频输入、麦克风就绪时序）。
- 界面层级：进入页 / 主界面 / 5 个顶部菜单 / 4 个弹窗均可正常展开、收起、切换；Esc 关闭菜单正常。
- 建议用户实测点：双机语音互通、屏幕共享观看端、PTT 手感、自动更新（安装版）。
