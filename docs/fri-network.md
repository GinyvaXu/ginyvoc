# 🌐 跨网络联机：SakuraFrp 穿透 / 蒲公英·米西·ZeroTier 组网

> 适用场景：**固定朋友开黑、不在同一局域网、不想买服务器、零预算**。
> 核心前提：GinyVoC 的**信令服务器**必须能被所有成员访问；而**语音/屏幕是 WebRTC P2P 直连**，走哪条「找到服务器」的路与语音质量没有直接关系。

## 0. 原理：信令 ≠ 媒体

```
开服者 PC ──┐                 ┌── 好友 PC
            │  ① 信令(找房间)   │   WebSocket(Socket.IO)
            └──► 服务器 ◄──────┘
                  │
  ② 语音/屏幕：双方浏览器 WebRTC P2P 直连（STUN 打洞），不经过服务器
```

- **信令**：极低频、小包（进房、换频道、交换 SDP/ICE），每月流量占用可忽略
- **媒体**：语音（Opus）+ 屏幕视频，P2P 直连，服务器零转发
- 结论：**内网穿透/组网只负责「让好友找到开服者的服务器」**；语音是否通畅取决于双方 NAT 能否打洞

## 1. 方案一：组网（推荐，语音最稳）

**通用流程**：所有人安装同一个组网工具并加入同一网络 → 开服者打开 GinyVoC「帮助 → 服务器设置」勾选「本机开服」，把「本机可访问地址」里的**虚拟 IP** 发给好友 → 好友勾选「连接朋友的服务器」填入 → 保存并重启。

### 1.1 蒲公英（贝锐）—— 门槛最低，国内稳定

| 免费额度 | 说明 |
|---------|------|
| 1 个网络 / 最多 3 个成员（含硬件和软件） | 超过需购买授权 |
| P2P 点对点不限速 | 经转发服务器时每节点 2 Mbps |

1. 官网 [pgy.oray.com](https://pgy.oray.com) 用手机号注册
2. 下载「蒲公英客户端」（Windows）并登录
3. 创建网络 → 邀请好友加入（好友也装客户端登录同一网络）
4. 确认各自拿到 `10.x.x.x` / `172.x.x.x` 开头的虚拟 IP
5. 开服者把**自己的虚拟 IP** 发给好友填入 GinyVoC 服务器设置

> 语音（Opus ≈ 24~64 kbps）在虚拟局域网内 P2P 直连，免费限速不影响。

### 1.2 米西开黑 —— 免费低延迟 P2P 组网

1. 下载「米西开黑」并登录
2. 创建联机房间（选对应游戏或通用）→ 好友加入同一房间
3. 成员头像右上角延迟变绿即组网成功
4. 开服者在 GinyVoC「本机可访问地址」里找到米西分配的虚拟 IP 发给好友

> 米西本身也带语音/视频/屏幕，可以**只用它组网**、继续用 GinyVoC 语音。

### 1.3 ZeroTier —— 备选（国际服务，国内偶尔不稳）

1. 注册 [my.zerotier.com](https://my.zerotier.com) → 创建 Network，记下 Network ID
2. 所有人安装 ZeroTier 客户端 → Join Network 填入 Network ID → 批准加入
3. 开服者把分配的 `10.x.x.x` 虚拟 IP 发给好友

## 2. 方案二：SakuraFrp 内网穿透（好友零安装）

只推荐给「开服者没有公网 IP、想让好友填一个公网地址直接访问」的场景。

### 免费额度（需实名）

| 项目 | 额度 |
|------|------|
| 隧道数量 | 2 条 |
| 单隧道带宽 | 10 Mbps |
| 每月流量 | 5 GiB（每日签到可增加） |
| 实名认证 | 必须（国内法规要求） |

### 创建 TCP 隧道步骤

1. 注册 [SakuraFrp](https://www.natfrp.com/) 并完成实名认证
2. 管理面板 → 创建隧道：
   - 类型：**TCP**
   - 本地地址：`127.0.0.1`
   - 本地端口：`3000`（GinyVoC 默认端口）
3. 下载并登录 SakuraFrp 启动器（Windows 客户端）→ 启动该隧道
4. 得到公网地址，形如 `123.45.67.89:23456`（随机远程端口）
5. 把地址发给好友：好友在 GinyVoC「帮助 → 服务器设置」→「连接朋友的服务器」填入 `123.45.67.89:23456` → 保存并重启

> 地址可以省略 `http://`（会自动补全）；不带端口时默认补 `3000`。

### 桌面版与浏览器版的差异

- **桌面版 exe**：远程明文 HTTP 已被标记为 Chromium 安全来源，**麦克风可直接用**
- **浏览器版**：明文 HTTP 下 `getUserMedia` 会被浏览器拦截，需 HTTPS → 用 SakuraFrp 的 HTTP/HTTPS 隧道并绑定自己的域名

### 防火墙与流量

- ✅ 隧道是**出站**连接，Windows 防火墙**无需放行入站**
- ⚠️ 每月 5 GiB 只消耗在信令/页面资源上（低频小包），日常开黑够用；**语音/屏幕不走隧道**

### 为什么语音不走隧道，还可能没声音

- 家庭宽带（Full Cone / 普通 NAT）→ STUN 打洞基本成功，语音 P2P 直连，延迟最低
- 校园网 / 公司网（对称 NAT）→ 打洞失败 → **能进房间但听不到声音**
- GinyVoC v0.6.0 起，打洞失败会在界面弹出诊断提示：「与 XX 的语音连接失败：公网打洞未成功，建议组网或检查防火墙」
- 遇到这种情况：改用**组网方案**（虚拟局域网内 NAT 变简单，语音基本必通），或按 README「进阶」配置 TURN 兜底

## 3. 三方案对比

| 维度 | 蒲公英 | 米西开黑 | SakuraFrp 穿透 |
|------|--------|---------|---------------|
| 客户端安装 | 所有人 | 所有人 | 只有开服者 |
| 免费额度 | 1 网络 / 3 成员 | 免费 P2P | 2 隧道 / 10 Mbps / 5 GiB/月 |
| 实名要求 | 手机号 | 手机号 | 必须实名认证 |
| 语音稳定性 | 最稳（虚拟网内 P2P） | 稳（P2P） | 取决于双方 NAT，严格 NAT 会失败 |
| 国内可用性 | 稳定 | 稳定 | 稳定，但流量有限 |
| 适用场景 | 2~3 人固定开黑 | 小圈子低延迟开黑 | 好友零安装、临时开黑 |

## 4. IPv6 直连（免装软件）

国内运营商宽带大多已分配公网 IPv6。双方都有 IPv6 时：

1. 开服者打开「服务器设置」，从「本机可访问地址」里找 IPv6 地址（形如 `http://[240e:xxxx:...]:3000`）
2. 发给好友 → 好友填入「连接朋友的服务器」→ 保存并重启

> 服务器已默认**双栈监听**（IPv4 + IPv6），无需额外配置。

## 5. 排查手册

| 现象 | 排查 |
|------|------|
| 好友能进房间但听不到声音 | 打洞失败 → 改用组网方案；确认双方系统防火墙允许 GinyVoC（WebRTC 用随机 UDP 端口） |
| 填了虚拟 IP 还是进不去 | 先 `ping 虚拟IP` 确认组网已通；再核对 GinyVoC 地址端口没写错 |
| SakuraFrp 隧道流量涨得很快 | 正常只消耗信令；若涨得异常，确认没人把视频/屏幕走了隧道 |
| 换网络后连不上 | 组网 IP / 隧道地址会变，重新查看并更新服务器设置 |
| 浏览器版连远程地址麦克风不可用 | 浏览器限制明文 HTTP 麦克风 → 用桌面版 exe，或给隧道绑定域名开 HTTPS |
